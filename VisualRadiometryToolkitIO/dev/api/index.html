VisualRadiometryToolkitIO.VisualRadiometryToolkitIO — Module
VisualRadiometryToolkitIO

The file formats of the Visual Radiometry Toolkit: the radiometric types of VisualRadiometryToolkitCore saved and loaded as self-describing files, in the envelope and under the schema rules of VisualGeometryToolkitIO.

Three kinds, each the serialization of one VisualRadiometryToolkitCore type, read and written by VisualGeometryToolkitIO's two verbs (this package adds the methods; import VisualGeometryToolkitIO as VgtkIO):

kindvaluereadwritten
vgio/vignetting/v2.0an AbstractVignetting (tensor-product, radial or log field)VgtkIO.load(AbstractVignetting, path)VgtkIO.save(path, v)
vgio/environment_light/v2.0an EnvironmentLight of a SphericalHarmonicMapVgtkIO.load(EnvironmentLight, path)VgtkIO.save(path, light)
vgio/radial_profile/v1.0a BinnedRadialProfileVgtkIO.load(BinnedRadialProfile, path)VgtkIO.save(path, p)

The kinds were VisualGeometryToolkitIO's up to its 0.10 and keep their schema names, so every file written before the move loads here, bit for bit; a vgio/vignetting/v1 or vgio/environment_light/v1 file reads through its version step. Each body is a value on VisualGeometryToolkitIO's VgioStyle (JSON.lower(style, value), JSON.lift(style, T, record)), so another package's record nests it, and each kind's table is public for a record that embeds the body (VIGNETTING_BODY, ENVIRONMENT_LIGHT_BODY, RADIAL_PROFILE_BODY).

Reading and writing

The kinds are read and written by VisualGeometryToolkitIO's two verbs, load and save (public there, not exported: import VisualGeometryToolkitIO as VgtkIO); this package adds the methods for its types.

VisualGeometryToolkitIO.save — Method
VisualGeometryToolkitIO.save(path, value::AbstractVignetting; provenance = (;))

Write a vignetting field — a TensorProductVignetting, RadialVignetting or LogVignetting — as a vgio/vignetting/v2.0 file: its type, degree, knots (a tensor surface's, stated) or centre, radius and chart (a radial profile's), and control points, positions in COLMAP pixels (the file's units.pixel). VisualGeometryToolkitIO.load(AbstractVignetting, path) gives the same field back, bit for bit, for a radial profile on its chart's own knots (the record holds no knots: a profile built from explicit knots reads back on its chart's rule). A field with no body (NoVignetting) is an ArgumentError.

source
VisualGeometryToolkitIO.load — Method
VisualGeometryToolkitIO.load(AbstractVignetting, path) -> AbstractVignetting

Read a vgio/vignetting/v2.0 file: the vignetting field save wrote, its positions moved from the file's units.pixel into COLMAP pixels (the fields' own). A v1 file (with or without its chart, which VisualGeometryToolkitIO 0.9 added inside v1) is read through its version step. A radial profile's knots are its chart's rule at its count and degree (projective_knots on the projective chart); a projective record of n ≤ 2p control points is refused (ArgumentError), the knots needing at least 2p + 1.

source
VisualGeometryToolkitIO.save — Method
VisualGeometryToolkitIO.save(path, light::EnvironmentLight; length_unit = mm, provenance = (;))

Write an EnvironmentLight of a SphericalHarmonicMap as a vgio/environment_light/v2.0 file: its centre and radius in length_unit (decimal-exact; a plain light — no units — is an ArgumentError naming with_unit(light, m)), and its coefficients per channel with the basis convention stated, in units.radiance ("relative"). VisualGeometryToolkitIO.load(EnvironmentLight, path) gives the same light back.

source
VisualGeometryToolkitIO.load — Method
VisualGeometryToolkitIO.load(EnvironmentLight, path) -> EnvironmentLight

Read a vgio/environment_light/v2.0 file: the light save wrote, its centre and radius lengths in metres. A v1 file is read through its version step.

source
VisualGeometryToolkitIO.save — Method
VisualGeometryToolkitIO.save(path, value::BinnedRadialProfile; provenance = (;))

Write a BinnedRadialProfile — a measured radial profile (a flat field binned by field angle) — as a vgio/radial_profile/v1.0 file: its chart (one of RADIAL_CHARTS: its centre and image-circle radius in pixels, the equisolid chart's focal length), the B + 1 bin edges in the chart's coordinate (radians for equisolid), the channels × B values (one row per channel) and the B pixel counts.

source
VisualGeometryToolkitIO.load — Method
VisualGeometryToolkitIO.load(BinnedRadialProfile, path) -> BinnedRadialProfile

Read a vgio/radial_profile/v1.0 file (save's): the profile exactly as written, its centre in COLMAP pixels (a file in another pixel frame moved into them).

The kinds and their tables

VisualRadiometryToolkitIO.VIGNETTING_KIND — Constant
VIGNETTING_KIND

The vgio/vignetting/v2.0 kind (a VisualGeometryToolkitIO.KindSpec): the envelope and one key, vignetting, the VIGNETTING_BODY. VisualGeometryToolkitIO.json_schema(VIGNETTING_KIND) is its JSON Schema and VisualGeometryToolkitIO.schema_versions(VIGNETTING_KIND) the versions read (vgio/vignetting/v1 through its version step).

The vgio/environment_light/v2.0 kind (a VisualGeometryToolkitIO.KindSpec): the envelope, then the keys of the ENVIRONMENT_LIGHT_BODY. vgio/environment_light/v1 reads through its version step.

VisualRadiometryToolkitIO.VIGNETTING_BODY — Constant
VIGNETTING_BODY

The table of the vignetting body (a VisualGeometryToolkitIO spec): an object told by its type, a tag of VisualRadiometryToolkitCore's VIGNETTING_TAGS — {"type": "tensor_product", "degree": [p, q], "knots_x", "knots_y", "control_points"}, {"type": "radial", "degree", "center", "radius", "chart", "control_points"} or {"type": "log", "spline": <a body>}. It is the vignetting key of a vgio/vignetting file (VIGNETTING_KIND), and the table a kind of another package states for a vignetting it embeds (PanoramaStitching's panorama), whose value it writes with JSON.lower(style, v) and reads with JSON.lift(style, AbstractVignetting, record).

source
VisualRadiometryToolkitIO.ENVIRONMENT_LIGHT_BODY — Constant
ENVIRONMENT_LIGHT_BODY

The table of the environment-light body (a VisualGeometryToolkitIO spec): {"center": [x, y, z], "radius": r, "map": {"type": "spherical_harmonics", "basis": "real_orthonormal_no_condon_shortley", "max_degree": L, "coefficients": [[…], …]}}, the lengths in the record's units.length, every channel holding (L + 1)² coefficients. They are the keys of a vgio/environment_light file (ENVIRONMENT_LIGHT_KIND), and the table a kind of another package states for a light it embeds, written with JSON.lower(style, light) and read with JSON.lift(style, EnvironmentLight, record).

source
VisualRadiometryToolkitIO.RADIAL_PROFILE_BODY — Constant
RADIAL_PROFILE_BODY

The table of the binned radial-profile body (a VisualGeometryToolkitIO spec): {"type": "binned_radial_profile", "chart": {"type", "center", "radius"[, "focal_length"]}, "edges", "values", "counts"} — B + 1 strictly increasing edges, one row of B values per channel, B counts each ≥ 0, the equisolid chart alone stating its focal length. It is the profile key of a vgio/radial_profile file (RADIAL_PROFILE_KIND), and the table a kind of another package states for a profile it embeds, written with JSON.lower(style, p) and read with JSON.lift(style, BinnedRadialProfile, record).

source
VisualRadiometryToolkitIO.migrate_vignetting_body — Function
migrate_vignetting_body(body::AbstractDict) -> AbstractDict

A vgio/vignetting/v1 body (a parsed record, String keys) as the v2.0 body: a radial profile states its chart — absent, the linear chart v1 read it in (VisualGeometryToolkitIO 0.8's body); present (VisualGeometryToolkitIO 0.9 wrote a non-linear profile's chart inside v1), as it stands. A log field's spline is a body too. The vgio/vignetting/v1 version step runs it, and so does the version step of another package's record that embeds a v1 body (PanoramaStitching's vgio/panorama/v1).

VisualRadiometryToolkitIO.json_schemas — Function
json_schemas() -> Vector{Pair{String, JSON.Object}}

The JSON Schemas (draft 2020-12) of this package's kinds, each generated from the kind's table (VisualGeometryToolkitIO.json_schema): path => schema, path the schema string followed by .json (vgio/vignetting/v2.0.json), the schema's $id that path below https://visualradiometrytoolkit.github.io/schemas/. JSON.json(schema; pretty = 4) is the published file (docs/src/schemas).
